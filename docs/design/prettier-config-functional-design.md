# Prettier 配置导入与导出：功能设计

状态：设计提案，尚未实现。日期：2026-09-22。

依据：[探索插件功能建议](codex://threads/01a0c817-0057-7a32-aea5-13877bbe0689) 最后两轮讨论；仓库基线 `fc32a1f`。配套文档：[代码设计](./prettier-config-code-design.md)。

## 1. 产品目标与核心决策

让用户在 Prettier Now 中调整格式化参数后，可以把配置直接带回项目；也可以把项目的静态配置导入扩展，复用其中受支持的核心选项和第三方插件选项。

本功能的主入口是「全屏工作台 → 设置 → 配置预设」。现有独立设置页面复用同一入口。浏览器工具栏 popup 继续负责打开工作台，不承载复杂配置表单。

确定以下设计原则：

1. **项目配置与扩展备份分开。** 前者面向项目中的 Prettier，后者保存扩展当前所有可持久化的格式化参数。
2. **插件由用户明确选择。** 支持某种语言，不代表导出的项目必须安装该语言插件。
3. **导入先分析、后应用。** 展示将改变的值、不能应用的内容及原因；选择文件本身不改变设置。
4. **只承诺受支持范围内的转换。** 不宣称任意项目配置都能在浏览器中等价运行。
5. **默认值以目标运行环境为准。** 精简导出比较 Prettier 和所选插件的默认行为，不能直接与扩展出厂设置比较。

Prettier standalone 不负责配置文件发现、读取和插件自动加载，因此配置解析与转换由扩展实现。[Prettier 浏览器文档](https://prettier.io/docs/browser)

## 2. 现状与能力边界

| 能力 | 当前实现 | 本设计的处理 |
| --- | --- | --- |
| 预设保存、应用、删除 | 已支持 | 保留 |
| 扩展格式化参数备份 | `prettier-now-options.json`，`version: 1` | 明确命名，兼容旧文件 |
| 标准 Prettier 配置导入 | 未支持 | 增加静态 JSON / YAML 导入 |
| 标准 Prettier 配置导出 | 未支持 | 增加 `.prettierrc.json` 导出 |
| XML / PHP / Java / Svelte / TOML 设置 | 有独立存储分组 | 按真实插件能力映射 |
| Pug 格式化 | 已支持，带浏览器适配 | 首期支持插件声明；专属可编辑选项后续补齐 |
| 工作台拖入文件 | 直接创建格式化任务 | 首期保留；第二阶段增加明确配置文件的意图选择 |
| 按文件路径应用 `overrides` | 未支持 | 首期报告并排除，单独设计后续支持 |

这里的「扩展格式化参数备份」包含核心和已存储的语言插件参数；**不包含主题、快捷键、历史记录、工作台文件，也不包含预设列表**。现有名称容易让人误以为是完整应用备份，需要在说明文字中澄清。

### 2.1 插件支持矩阵

| 语言插件 | 项目中的标准包名 | 首期插件声明 | 首期可导入／导出选项 |
| --- | --- | --- | --- |
| XML | `@prettier/plugin-xml` | 支持 | `xmlQuoteAttributes`、`xmlSelfClosingSpace`、`xmlSortAttributesByKey`、`xmlWhitespaceSensitivity` |
| PHP | `@prettier/plugin-php` | 支持 | `braceStyle`、`phpVersion`、`trailingCommaPHP`；值域以扩展当前可保存范围为准 |
| Java | `prettier-plugin-java` | 支持 | 核心选项；旧 `entrypoint` 需按版本能力处理，见下文 |
| Svelte | `prettier-plugin-svelte` | 支持 | `svelteAllowShorthand`、`svelteIndentScriptAndStyle`、`svelteSortOrder` |
| TOML | `prettier-plugin-toml` | 支持 | 当前设置中的 11 个专属选项 |
| Pug | `@prettier/plugin-pug` | 支持 | 暂无用户可保存的专属选项；导入的 `pug*` 配置逐项提示未支持 |

JavaScript、TypeScript、Vue、HTML、CSS、JSON、YAML、Markdown、GraphQL 等已有内置支持的语言不生成额外 npm 插件依赖。浏览器代码中的 `prettier/plugins/*` 是运行时加载细节，不直接转成项目依赖列表。

「已支持插件」不等于「支持该插件的全部选项」。面板应显示具体状态，例如「Pug：支持导出依赖声明，暂不导入专属选项」。

### 2.2 当前已核实的兼容性问题

基于本地安装包读取到以下信息，实施时应以锁文件和行为测试复核：

| 情况 | 对用户行为的影响 |
| --- | --- |
| 扩展 `endOfLine` 默认 `auto`，Prettier 3.9.8 默认 `lf` | 即使没有手动修改，精简导出也应保留 `endOfLine: "auto"` |
| PHP 0.25.0 默认 `phpVersion: "auto"`，扩展目前保存具体版本且默认 `7.0` | 导出需保留 `7.0`；导入 `auto` 提示「扩展暂不支持此值」，不能偷偷改成 `7.0` |
| PHP 声明 `defaultOptions.tabWidth: 4` | 选择 PHP 时，当前 `tabWidth: 2` 不能只因等于 Prettier 核心默认值而删除 |
| Java 2.10.4 声明 `defaultOptions.arrowParens: "avoid"` | 导出时保守保留当前显式值，避免插件默认值影响结果 |
| Java 2.10.4 的选项元数据未声明 `entrypoint`，扩展仍保存该字段 | 暂不导出该历史字段；非默认值必须提示可能无法迁移，不能据旧类型宣称支持 |
| Svelte 声明了扩展未提供的 `svelte5CompilerPath` | 识别为插件选项但不可在扩展应用，不读取用户项目路径 |

## 3. 功能分期

| 阶段 | 交付范围 | 完成标准 |
| --- | --- | --- |
| P0：设置内闭环 | JSON / YAML 导入、诊断与差异预览、合并应用、六类插件选择、项目 JSON 导出、安装命令、备份入口澄清 | 已支持参数可以往返转换；不支持内容可见且不被静默应用 |
| P1：输入体验与 Pug | 明确配置文件拖入时选择用途；Pug 专属参数建模、存储、备份版本升级 | 普通拖拽不受影响；Pug 参数在工作台和网页格式化均生效 |
| P2：项目规则 | 工作区路径上下文、`overrides` 匹配、配置文档独立保存 | 多文件格式化按相对路径使用正确规则 |

P0 不执行 JS / TS 配置，不导入共享配置包，不处理 `.editorconfig`、`.prettierignore`、TOML / JSON5 配置或 `package.yaml`，不安装任意第三方插件。

Pug 配置补齐与拖拽可分别交付。`overrides` 不应以简单展开对象的方式提前实现。

## 4. 入口与页面结构

「配置预设」区分三个区域，使用文字按钮说明用途：

```text
配置预设
  预设名称 [________________]  [保存预设]
  已有预设 [下拉选择________]  [应用] [删除]

项目 Prettier 配置
  将格式化参数与项目共享，支持核心选项和已集成插件。
  [导入项目配置]  [导出项目配置]

扩展格式化参数备份
  保存当前所有格式化参数，用于在 Prettier Now 中恢复。
  [备份参数]  [恢复参数]  [重置参数]
```

点击导入或导出后，在当前设置容器中进入对应子面板。标题区提供「返回配置预设」。使用现有 Dialog 的内容区域，不在 Dialog 内叠加第二层模态窗口。

独立设置页面也渲染同一子面板。桌面宽度采用左右分栏；窄窗口按设置、预览、操作顺序排列。底部操作区固定在面板内，不遮挡最后一行内容。

返回时放弃未应用的导入草稿；它尚未影响设置，无需再弹确认。关闭后清除文件内容，不把完整导入文件存入浏览器存储。

## 5. 项目配置导出

### 5.1 操作流程

1. 打开面板，读取已经完成初始化的当前格式化参数，生成本次导出的快照。
2. 用户勾选项目需要的语言插件。首次打开全部不勾选，不从历史代码或当前语言自动决定。
3. 默认勾选「仅导出非默认值」。说明文字为「与当前内置 Prettier 和所选插件的默认值比较」。
4. 实时生成只读 JSON 预览、依赖安装命令及必要的兼容性提示。
5. 用户点击「复制配置」或「下载 .prettierrc.json」。下载和复制使用同一份字符串。

本次会话中可以保留所选插件和包管理器；P0 不把这些偏好混入格式化参数快照。若同一页面内当前设置已变化，提示「配置已变化，刷新预览」，暂停复制和下载；刷新快照并重新生成可见预览后才能继续。

### 5.2 面板内容

```text
← 返回配置预设                   导出项目配置

核心格式化选项：包含

项目需要的语言插件
  [ ] XML     [ ] PHP      [ ] Java
  [ ] Svelte  [ ] TOML     [ ] Pug

[✓] 仅导出非默认值

配置预览                         .prettierrc.json
┌─────────────────────────────────────────────┐
│ {                                           │
│   "endOfLine": "auto",                      │
│   "semi": false                             │
│ }                                           │
└─────────────────────────────────────────────┘

依赖安装   [pnpm ▾]              [复制安装命令]
pnpm add -D -E prettier@3.9.8

                              [复制配置] [下载]
```

版本号来自构建时解析的安装版本，示例数字不应写死在界面逻辑中。

### 5.3 导出规则

| 项目 | 规则 |
| --- | --- |
| 核心选项 | 始终参与导出；精简模式可删除可证明等于目标默认值的字段 |
| 语言插件选项 | 仅包含选中插件拥有且可移植的字段 |
| `plugins` | 使用标准 npm 包名；去重；按界面固定顺序输出；没有插件时省略 |
| 核心字段被插件重新声明 | 仍只有一个字段，例如 PHP 的 `singleQuote` 不重复导出 |
| 默认值未知或受环境影响 | 保留显式值，不猜测 |
| 插件会改变核心默认值 | 保守保留受影响字段，如 PHP 的 `tabWidth` |
| 历史／失效字段 | 不直接输出；非默认值列入兼容性提示 |
| 内部字段 | 不导出 `version`、分组名称、`languageId`、运行时 `parser`、文件路径和插件对象 |
| 输出格式 | JSON、两空格缩进、LF、末尾换行、稳定字段顺序 |

关闭精简模式表示「导出全部受支持的可移植参数」，并不表示导出所有扩展内部字段或所有第三方插件可能提供的参数。

示例：当前 `semi: false`、`endOfLine: auto`、`tabWidth: 2`、PHP 目标版本 `7.0`，选择 PHP 和 XML，XML 选项保持默认，预期保留：

```json
{
  "plugins": ["@prettier/plugin-xml", "@prettier/plugin-php"],
  "endOfLine": "auto",
  "phpVersion": "7.0",
  "semi": false,
  "tabWidth": 2
}
```

### 5.4 安装命令

支持 pnpm、npm、yarn、bun，默认 pnpm。命令仅供复制，扩展不执行安装。

| 包管理器 | 命令模板 |
| --- | --- |
| pnpm | `pnpm add -D -E prettier@<版本> <插件包>@<版本>` |
| npm | `npm install -D -E prettier@<版本> <插件包>@<版本>` |
| yarn | `yarn add -D -E prettier@<版本> <插件包>@<版本>` |
| bun | `bun add -d --exact prettier@<版本> <插件包>@<版本>` |

只生成当前扩展已集成且用户选中的插件名。PHP、Svelte 在项目中使用包的根入口，不输出 `/standalone`、`/browser`。

精确版本有助于复现，但扩展的 Pug 带本地浏览器兼容补丁。因此不承诺项目环境与扩展对所有输入字节级一致；选中 Pug 时展示简短兼容性说明，实施阶段用代表性输入验证。

## 6. 项目配置导入

### 6.1 输入格式

| 输入 | P0 行为 |
| --- | --- |
| `.prettierrc` | 支持 JSON / YAML 对象 |
| `.prettierrc.json`、普通 `.json` | 作为 JSON 配置读取；普通文件仅通过显式导入入口处理 |
| `.prettierrc.yaml`、`.prettierrc.yml`、普通 YAML | 作为 YAML 配置读取 |
| `package.json` | 只读取其中对象形式的 `prettier` 字段；没有字段则说明，不把整个文件作为选项 |
| 粘贴文本 | 提供 JSON / YAML 格式选择，默认 JSON；不猜测 JavaScript |
| `.js/.mjs/.cjs/.ts/.mts/.cts` | 提示仅支持静态配置，不执行代码 |
| JSON5、TOML、共享配置字符串 | 提示当前版本不支持 |
| 扩展备份 JSON | 提示「这是扩展参数备份」，提供进入恢复流程的操作，不自动恢复 |

P0 每次只导入一个文件；文件及粘贴内容均限制为 1 MiB。此值是产品限额，使用统一常量；超限保留当前设置并提示。

### 6.2 分析与预览

```text
← 返回配置预设                   导入项目配置

[选择文件]  [粘贴配置]
来源：.prettierrc.yaml

应用方式
  (●) 合并到当前设置：未声明的选项保持不变
  ( ) 先恢复扩展默认参数，再应用已识别选项

将修改 3 项；保持 39 项；有 2 项不能应用
选项                  当前值              导入后
semi                  true                false
tabWidth              2                   4
xmlQuoteAttributes    preserve            double

不能应用的内容
  plugins[1]：扩展未集成该插件
  overrides：当前不支持按文件规则

[ ] 我理解以上内容不会应用，也不会保存在后续导出中

                        [取消] [仅应用受支持选项]
```

示意中的数量由实际差异计算。修改模式、重新选择文件或编辑粘贴内容，都重新分析，并清除已勾选的忽略确认。

默认「合并」只覆盖文件明确声明且验证通过的选项。第二种方式以**扩展默认参数**补齐所有分组，再覆盖已识别选项；名称与预览必须说明这不是 Prettier 项目的隐式默认值。例如输入 `{ "semi": false }` 不等价于解析整个项目配置。

首期不提供自动与项目行为完全对齐的替换模式，因为 PHP 的 `auto` 等值尚不能在当前设置模型中表示。

### 6.3 字段分类与处理

| 分类 | 例子 | 行为 |
| --- | --- | --- |
| 已支持核心选项 | `semi: false` | 校验后应用 |
| 已支持插件选项 | `xmlQuoteAttributes: "double"` | 按登记的所属分组应用 |
| 插件选项未写 `plugins` | 仅有 `xmlSelfClosingSpace` | 若归属唯一，识别为 XML；提示已由选项推断插件；不视为安装请求 |
| 已集成插件声明 | `@prettier/plugin-php` | 识别并显示；扩展已有加载能力，不动态下载 |
| 未集成插件 | `prettier-plugin-tailwindcss` | 列入不能应用清单，保留原值供查看 |
| 已知插件但选项未建模 | `pugSingleQuote` | 明确说明插件可格式化，但该配置尚不能保存 |
| 已知选项但值暂不支持 | `phpVersion: "auto"` | 与语法错误区分，列入兼容性提示；不自动改值 |
| 已支持选项的非法值 | `semi: "false"`、`tabWidth: -2` | 阻止本次应用，定位字段 |
| 未知字段 | `myCustomOption` | 列入不能应用清单，不按前缀猜测归属 |
| `$schema` 字符串 | JSON Schema URL | 视为编辑器元数据；不访问 URL、不应用到格式化器 |
| `overrides` | 按文件配置数组 | 显示规则数量和原始结构，整体排除；不能提升为全局参数 |
| 顶层 `parser` | `typescript` | 列入不能应用清单；继续由任务语言决定解析器 |
| 运行时控制字段 | `filepath`、`rangeStart`、`cursorOffset` | 不导入全局设置，逐项说明 |

官方配置支持通过 `overrides` 针对文件应用规则，并建议不要在顶层设置 `parser`。P0 以诊断方式处理这些内容。[Prettier 配置文档](https://prettier.io/docs/configuration)

### 6.4 应用门槛

- 语法错误、根节点不是对象、字段值错误或结构错误：禁止应用。
- 存在不能应用的字段、插件或规则：必须先勾选忽略说明，按钮使用「仅应用受支持选项」。
- 文件只有插件声明而没有可应用选项：显示识别结果，不修改设置；不能借此把所有选项重置。
- 没有可应用选项：禁用应用，即使选择了恢复默认模式。重置操作应走专门入口。
- 有合法选项但最终差异为零：显示「当前设置已一致」，不重复写入存储。
- 分析期间或设置尚未读取完成：禁用应用。
- 预览后同页面设置发生改变：要求重新生成差异，不能把过期预览直接应用。

不能应用的内容只保留在当前导入会话中。后续「导出项目配置」基于当前有效设置生成文件，不负责还原刚才导入的原始文档。这一限制在部分导入确认中明确说明。

### 6.5 应用后的行为

应用影响扩展的全局格式化参数。当前工作台后续格式化，以及持久化完成后的网页编辑器格式化，使用新参数。已经打开的其他工作台窗口沿用现有存储同步能力；P0 不新增跨窗口即时同步保证。

不自动重新格式化所有文件，不覆盖源代码，不新增格式化历史。当前结果显示「配置已更新，请重新格式化」；使正在进行的旧配置格式化请求失效，避免旧结果覆盖新状态。用户可主动格式化当前文件或全部文件。

成功后返回配置预设。用户可以沿用「保存预设」为当前参数命名，不在一次导入中同时引入第二套预设保存流程。

应用失败保留分析结果，允许重试或返回。语法和验证失败不产生任何设置修改；持久化失败需要显示明确错误，不能只在控制台记录。

## 7. 扩展备份与恢复

继续生成和读取 `prettier-now-options.json`。P0 保持 `OptionsSnapshot.version: 1` 和现有分组结构。

恢复时沿用完整快照验证，但增加覆盖前的参数差异预览；成功后替换全部格式化参数。预设列表、历史记录和用户界面配置保持原样。

项目导入与备份恢复必须明确区分。检测到备份文件后进入恢复预览，仍需要点击应用。反向情况则提示使用项目配置导入。

未来增加 Pug 可持久化参数时升级备份版本，提供 v1 → v2 迁移：缺少的 Pug 分组补入明确的默认值；已有预设一起兼容读取。旧版本不能读取新备份时必须报不支持版本，不能装作成功。

## 8. 第二阶段的拖拽行为

只按明确文件名识别候选配置：`.prettierrc`、`.prettierrc.json`、`.prettierrc.yaml`、`.prettierrc.yml`。

| 场景 | 行为 |
| --- | --- |
| 单个普通代码文件 | 保持直接格式化 |
| 单个明确配置文件 | 显示「应用为格式化配置」「格式化此文件」「取消」 |
| 普通 JSON / YAML / `package.json` | 保持作为代码格式化；配置导入走设置入口 |
| 配置与代码混合拖入 | 先展示批次选择，不开始格式化；提供「导入这一份配置后格式化其余文件」或「全部作为文本格式化」 |
| 一次拖入多个配置 | 不自动合并；选择其中一个导入，其余可作为文本处理或跳过 |
| 取消意图选择或导入预览 | 整个待处理批次取消，保留现有工作台 |

`.prettierrc` 没有常规扩展名，选择「格式化此文件」时需单独判断 JSON / YAML 语言。该选择不改变全局参数。

拖拽面板只负责收集意图，最终复用设置中的导入分析与应用流程。设置子面板打开时，工作台全局拖拽监听不应接管事件或显示遮挡层。

## 9. 无障碍、国际化与错误反馈

- 导入、导出、备份使用文字按钮；图标仅作为辅助。
- 插件复选框、模式选择、粘贴输入均有可见标签。
- 面板切换后焦点进入标题；返回后回到触发按钮；Esc 遵循现有设置容器行为。
- 分析完成与复制结果使用状态提示；字段错误保留在面板内，并提供字段路径及可用时的行列位置。
- 配置预览可选择复制；长错误列表可滚动，应用按钮保持可达。
- 文件名、选项键和诊断值以文本显示，不渲染为 HTML。
- 同步更新 `en`、`zh-CN`、`zh-TW`、`ja`、`ko`；包名和选项键不翻译。

推荐错误文案包括：「这不是配置对象」「第 8 行有语法错误」「phpVersion 的此值暂不能在扩展中保存」「部分配置不会应用」「参数已在当前页面应用，但保存失败，请重试」。

## 10. 功能验收清单

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| F01 | 当前 `semi: false`，不选择插件并导出 | 文件不含 `plugins`，保留 `semi: false` 和必要默认差异 |
| F02 | 选择 PHP，扩展 `tabWidth: 2` | 精简导出仍包含 `tabWidth: 2`、有效 PHP 选项与标准包名 |
| F03 | 选择 XML 但所有 XML 选项等于插件默认值 | 保留插件声明，省略默认专属选项 |
| F04 | PHP、Svelte 安装命令 | 使用包根名，版本与构建使用的依赖一致 |
| F05 | 导入 JSON / YAML 的 `semi: false` | 差异相同；合并模式仅修改明确声明字段 |
| F06 | 导入 `semi: "false"` | 提示字段错误，无任何参数修改 |
| F07 | 导入未知插件或 `overrides` | 不静默忽略；必须确认后才可应用其余选项 |
| F08 | 导入 PHP `auto` 或 Pug 专属选项 | 显示能力限制，不伪造等价配置 |
| F09 | 导入旧备份 | 识别为备份，完整预览和恢复，预设列表不变 |
| F10 | 取消、空文件、超限文件、解析过程中返回 | 不改变参数，不出现延迟应用 |
| F11 | 应用后再次格式化工作台与网页编辑器 | 使用已保存的新参数；旧请求不回写结果 |
| F12 | 精简开关切换、复制与下载 | 预览及时更新，复制内容和下载内容一致 |
| F13 | 原普通文件拖拽 | P0 行为不变；P1 仍直接格式化 |
| F14 | 键盘操作、窄窗口、深色模式 | 所有选择和操作可达，内容不溢出 |
| F15 | 两个设置入口 | 工作台 Dialog 和独立设置页行为一致 |

发布说明应使用「支持已集成插件的项目配置导入／导出」，并附具体支持矩阵，避免表述为所有 Prettier 配置完全兼容。
